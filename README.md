# Batoot Casino v2

بوت اقتصاد وألعاب Discord مبني على Discord.js v14.

## التشغيل
1. استخدم Node.js 18.17 أو أحدث.
2. نفّذ `npm install`.
3. أضف `DISCORD_TOKEN` إلى متغيرات الاستضافة.
4. فعّل Message Content Intent وServer Members Intent من Discord Developer Portal.
5. شغّل `npm start`.

## الإعدادات
- `OWNER_ID`: آيدي الأونر.
- `GUILD_ID`: آيدي السيرفر.
- `ADMIN_IDS`: آيديّات الإداريين المسموح لهم بأوامر إدارة الرصيد، مفصولة بفواصل.
- `GAME_CHANNEL_IDS`: رومات الألعاب مفصولة بفواصل.
- `WITHDRAW_PANEL_CHANNEL_ID`: روم لوحة السحب.
- `WITHDRAW_REQUESTS_CHANNEL_ID`: روم مراجعة طلبات السحب.
- `PROBOT_ID`: آيدي ProBot.
- `GITHUB_TOKEN`: توكن GitHub بصلاحية Contents Read and write للنسخ الاحتياطي (ضروري حتى لا تضيع البيانات عند إعادة نشر الاستضافة).
- `GITHUB_REPOSITORY`: المستودع المستخدم للنسخ الاحتياطي.
- `GITHUB_DATA_BRANCH`: فرع البيانات، الافتراضي `bot-data`، وينشئه البوت تلقائياً إذا لم يكن موجوداً.
- `GITHUB_BASE_BRANCH`: الفرع الذي تُنشأ منه نسخة البيانات أول مرة، الافتراضي `main`.

### تفعيل حفظ البيانات الدائم
1. أنشئ GitHub Personal Access Token بصلاحية Contents: Read and write على مستودع البوت.
2. أضف التوكن في متغيرات الاستضافة باسم `GITHUB_TOKEN` فقط؛ لا تضعه داخل ملفات المشروع ولا ترسله في Discord.
3. تأكد أن `GITHUB_REPOSITORY` يساوي `hasanalbably905-oss/Casinooooo-` أو اسم مستودعك الصحيح.
4. شغّل البوت. سينشئ فرع `bot-data` تلقائياً ويحفظ `data/store.json` فيه بعد كل حفظ، مع حفظ احتياطي كل دقيقة.
5. عند إعادة التشغيل يسترجع البوت بيانات الأعضاء وكل مجموعات البيانات من الفرع قبل تسجيل الدخول.

إذا لم يكن `GITHUB_TOKEN` مضبوطاً، فالحفظ المحلي وحده لا يضمن بقاء البيانات بعد حذف ملفات الاستضافة أو إعادة نشرها.
- `DISCORD_TOKEN`: توكن البوت (مطلوب).

## أوامر الأعضاء
- `فلوس`: عرض رصيدك. ويمكن استخدام `فلوس @عضو` لعرض رصيد عضو.
- `يومي`: مكافأة يومية كل 24 ساعة.
- `عمل`: مكافأة عمل كل ساعة.
- `ملفي`: ملفك وإحصائياتك. ويمكن استخدام `ملفي @عضو`.
- `تحويل @عضو مبلغ`: إنشاء طلب تحويل يتطلب تأكيد المرسل.
- `تحويلاتي`: آخر 10 تحويلات مكتملة لك.
- `توب`: أعلى 10 أرصدة.
- `تحدي @عضو مبلغ`: بدء تحدٍ في رومات الألعاب المحددة.
- `withdraw`: عرض لوحة السحب في روم السحب.
- `مساعدة`: عرض قائمة الأوامر.

## أوامر الأونر والإدارة المعتمدة
- `add @عضو مبلغ`: إضافة رصيد.
- `rmv @عضو مبلغ` أو `remove @عضو مبلغ`: خصم رصيد.
- `سجل-اداري`: عرض آخر 10 عمليات إضافة وخصم.

## التحويلات
التحويل بين الأعضاء لا يتم مباشرة؛ ينشأ طلب لمدة دقيقتين، ويستطيع صاحب الطلب وحده تأكيده أو إلغاءه. لا يُخصم الرصيد إلا بعد التأكيد، وتُحفظ تفاصيل العملية وحالتها وأطرافها.

## الألعاب
- النرد: يرمي كل لاعب 3 مرات بالتناوب، وتُجمع نتائج الرميات الثلاث؛ صاحب المجموع الأعلى يفوز، والتعادل يعيد الرهانين.
- الرقم التقريبي: اللاعبان يحاولان الاقتراب من الرقم السري.
- رسوم الفوز 4%. التعادل يعيد الرهانين.
- الرهانات تُحجز عند قبول التحدي وتُعاد تلقائياً عند انتهاء المهلة.

## السحب
طلب السحب يحجز الكوينات حتى تراجع الإدارة. الرفض يعيد الرصيد. الموافقة تسجل القرار؛ التسليم الخارجي يدوي من الإدارة.

## حماية الشحن والسحب
- شحن ProBot يُضاف تلقائياً فقط إذا وفرت المكتبة معرّف عملية فريداً يمكن حفظه لمنع تكرار الإيداع.
- إذا لم يتوفر معرّف فريد، لا يضيف البوت الرصيد تلقائياً؛ ينشئ مراجعة في روم الطلبات بأزرار اعتماد/رفض للإدارة. يجب التحقق من سجل تحويل ProBot قبل الاعتماد.
- إذا تعذّر نشر طلب سحب بسبب توقف البوت، يعيد البوت نشر الطلبات المعلّقة عند التشغيل.
- تُرفض أي إضافة رصيد تتجاوز الحد الآمن للأرقام في JavaScript.
- عند تعارض نسخة GitHub، يوقف البوت الكتابة البعيدة بدلاً من استبدال نسخة أحدث ببيانات قديمة.

## حفظ البيانات
- البيانات المحلية في `data/store.json`.
- يشمل الحفظ الأرصدة والألعاب والسحب والتحويلات وسجل عمليات الإدارة ومواعيد المكافآت.
- النسخ الاحتياطي إلى فرع GitHub مستقل `bot-data`.
- لا تحذف مجلد `data` عند إعادة النشر، ولا ترفع ملف `.env` أو أي توكن إلى GitHub.
- عند أول تشغيل يستورد البوت الأرصدة القديمة من `data/databaseusers.json` أو `db.json` إن وُجدا.

الأرصدة كوينز افتراضية داخل البوت؛ لا يوجد دفع أو تحويل أموال حقيقي مدمج.
